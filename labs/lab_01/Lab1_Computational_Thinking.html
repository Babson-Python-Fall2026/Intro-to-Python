Part 1 — Draw an X Inside a Square

File: labs\lab_01\draw.py

Problem

Ask the user for an odd integer representing the size of a square. Print a square made from * characters with an X drawn inside it.

The outside border of the square should be stars. The two diagonals that form the X should also be stars. All other positions should be spaces.

Example output

For a size of 7, your output should look like this:

*******
**   **
* * * *
*  *  *
* * * *
**   **
*******
Requirements
  • Prompt the user for the square size.
  • You may assume the user enters an odd integer of at least 3.
  • Your solution must work for different odd sizes, not just 7.
  • Use loops and conditional logic to decide what to print at each position.
  • Do not hard-code the finished picture.

Before you code

1. For a given row and column, what conditions tell you that the position belongs to the outside border?
2. What relationship between the row number and column number identifies one diagonal?
3. What relationship identifies the other diagonal?

After you code

Briefly explain how your program decides whether each position should contain a star or a space.

Part 2 — Generate Random Student Test Data

File: labs\lab_01\generate.py

Background

When testing programs, it is often useful to create random input data instead of typing many test records by hand. For this exercise, you will write a function that generates random student records.

Problem

Write a function that takes N as a parameter, where N is the number of student records to generate and return.

Each student record must be a dictionary with exactly these keys:

'id'
'fname'
'mi'
'lname'

mi stands for middle initial.

Data to use

Inside your function, hard-code three lists:

  • fname — at least 5 unique first names
  • mi — the letters A through Z
  • lname — at least 5 unique last names

If you use exactly 5 first names and 5 last names, then there are: 

5 × 26 × 5 = 650

possible unique combinations of first name, middle initial, and last name.

Requirements
  • Place import random at the top of your program.
  • Look up the functions available in the random library that may help you.
  • The function must return exactly N student dictionaries.
  • Student IDs must be sequential integers starting with 1.
  • The combination fname + mi + lname must be unique for every returned student.
  • Your function must prevent the request from exceeding the number of unique student-name combinations your lists can produce.
  • Do not simply type out the student records manually.

Example of one student dictionary

{
    'id': 1,
    'fname': 'Maya',
    'mi': 'Q',
    'lname': 'Chen'
}

Your names may be different. The example only shows the required structure.

Questions to answer

1. What data structure does your function return? Why is that structure a good choice for a collection of student records?
2. How does your program make sure that two students do not receive the same first-name, middle-initial, last-name combination?
3. What should happen if the requested value of N is larger than the number of unique records your lists can produce?

Part 3 — Caesar Cipher

File: labs\lab_01\caesar.py

What is a Caesar cipher?

A Caesar cipher replaces each letter with another letter a fixed number of positions away in the alphabet. When the shift passes the end of the alphabet, it wraps back to the beginning.

For example, with a shift of 3:

A → D
B → E
C → F
...
X → A
Y → B
Z → C

With a shift of 8, the word hello becomes PMTTW if your program produces uppercase output.

Your task

Write a program that can both encrypt and decrypt text using a Caesar cipher.

Requirements
  • Ask the user for the text.
  • Ask the user for an integer shift value.
  • Ask whether the user wants to encrypt or decrypt.
  • Convert the input text to uppercase before processing it.
  • Leave spaces, punctuation, and digits unchanged.
  • Your program must handle shift values greater than 26.
  • Your program must handle negative shift values.
  • Your program must correctly wrap from the end of the alphabet back to the beginning.
  • You may not use ord() or chr().
Important: You are expected to determine your own representation and lookup strategy. The lab is intentionally not prescribing the exact data structures or steps you should use.

Example

Input Value
Text Hello, Bob!
Shift 3
Mode Encrypt

Output:

KHOOR, ERE!

Questions to answer

1. How did you represent the alphabet in your program?
2. Explain how your program handles wraparound. For example, why does shifting Z forward by 3 produce C?
3. What should happen when the shift value is negative? Use an example to explain your answer.
4. What should happen when the shift value is exactly 26? Why?
5. What effective shift should your program use when the user enters 300? Explain how you determined it.
6. Why should a shift of 29 have the same effect as a shift of 3?
7. How does your decryption logic reverse the encryption?

Reflection

Answer each question in complete sentences.

  1. Which of the three problems required the most planning before you began coding? Why?
  2. Choose one problem and explain how you broke it into smaller pieces.
  3. Describe one important data-representation decision you made in Part 2 or Part 3.
  4. Describe one bug you encountered or one test case that helped you discover a problem in your code.
  5. If you had to make one of your solutions work for a much larger input, what part of your approach would you reconsider first?
