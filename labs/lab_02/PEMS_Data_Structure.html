PEMS: Portfolio Data Structure

Computational Thinking with AI & Python · Capstone Reference

Design principle: Client transactions are the source of truth. Holdings, cash balances, and reports are calculated from transaction history—not stored as separate balances.

1. System-maintained JSON files

FilePurpose
pm_users.jsonPortfolio manager login records (including password verification data). The manager initials identify each user.
pems.jsonPortfolio manager client lists and each client's transaction history.

When pems.json is loaded, its top-level Python dictionary is named pems. The spelling and capitalization should be consistent throughout the project.

clients[0]dictionary
name, email, phonestrings

4. Transaction dictionary

FieldMeaning
trans_idInteger transaction identifier, sequential within a client.
trd_dayInteger simulated trading-day number.
tickerSecurity ticker, or $$$$ for cash.
trn_typeTransaction action, such as BUY, SELL, CONTRIBUTION, or WITHDRAWAL. The action determines direction.
sharesNonnegative quantity involved in the transaction; for cash, the quantity represents dollars because each cash unit is worth $1. Do not use a negative sign to encode direction; trn_type determines addition versus subtraction.
cpsCost per share (for cash, 1.0). The precise interpretation for sells and corporate actions must be consistent with the cost-basis rules.
total_costTransaction's associated total cost basis, using the project's consistent accounting rules.

Direction comes from trn_type

TypeTickerSharesEffect
CONTRIBUTION$$$$10000Add $10,000 cash
WITHDRAWAL$$$$2000Remove $2,000 cash
BUYAAPL100Add 100 AAPL shares; cash decreases
SELLAAPL40Remove 40 AAPL shares; cash increases

5. Program state and client_idx

client_idx is the zero-based list index of the currently selected client. It is part of temporary program state, not a field in pems.json. We do not need a separate client ID because clients are not deleted or reordered in this project.

state = {
    "pm": current_pm,
    "pems": pems,
    "clients": pems[current_pm]["clients"],
    "client_idx": None,
    "trd_day": 1,
    "market_data": market_data,
    "security_info": security_info
}

When selecting client number 1 from a numbered menu:

state["client_idx"] = choice - 1  # First client: index 0
client = state["clients"][state["client_idx"]]
print(client["name"])

Important: Test state["client_idx"] is not None, not if state["client_idx"], because index 0 is a valid first client.

6. Creating clients and recording transactions

Create a new client by appending its completed dictionary to the manager's clients list:

clients = state["clients"]
client = {
    "name": name,
    "email": email,
    "phone": phone,
    "transactions": [transaction]
}
clients.append(client)

For an existing client, do not append the client again. Append only the transaction:

client = state["clients"][state["client_idx"]]
client["transactions"].append(transaction)

state["clients"] refers to the same list contained in state["pems"][state["pm"]]["clients"], so these changes update pems in memory.

7. Loading, saving, and persistence

import json

with open("labs/#capstone/data/pems.json", "r", encoding="utf-8") as file:
    pems = json.load(file)

# The instructor supplies save_pems(state).
# After successfully creating a client:
save_pems(state)

# The supplied helper writes state["pems"] to pems.json.

Students do not write the save_pems(state) helper; it is provided. Memory vs. disk: append() changes the live objects in memory. json.dump() writes those changes back to pems.json. Reports ordinarily only read data and do not require saving.

Unlike the earlier dictionary-of-clients design, this list-of-clients design needs no conversion of client ID keys when loading JSON.

8. What is not stored in pems.json?

Current holdings, cash balances, and the selected client's index are not stored. Holdings and cash are reconstructed from transactions. client_idx, current menu stack, and other interaction details live only in program state.
