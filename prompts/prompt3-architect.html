The Four Design Elements

These four elements are now required before AI writes any code. Learning to identify them accurately is the core skill of this phase of the course — and the skill that the final exam is designed to assess.

Element 01

Inputs

What data does the program receive? From the user, from a file, from a function argument? Be specific about type and format.

Element 02

State

What variables hold information that changes as the program runs? The state is what the program "remembers" between steps.

Element 03

Transitions

What causes the state to change? A user action, a loop iteration, a function call? Name the specific events that update the state.

Element 04

Invariants

What must always remain true, no matter what inputs arrive or transitions occur? These are the rules your program must protect.

Why invariants matter most

Invariants are the hardest element to identify — and the most valuable. A portfolio balance can never be negative. A list index can never exceed the list length. A quantity can never be fractional for whole-unit items. Finding your invariants before you write code means you know exactly what your code needs to protect. AI will often miss invariants unless you name them explicitly.

Apply the four elements to the equity portfolio system. For the operation "add a new stock position to the portfolio," identify all four elements before looking at any code.

The Required Conversation Workflow

With Prompt 3, every non-trivial problem follows this sequence. The pseudocode gate is a hard stop — AI cannot write Python until you have submitted pseudocode and AI has confirmed it is logically correct.

1
You

Paste the prompt with your question. AI confirms workbook is uploaded and asks for your design.

2
You

Identify inputs, state, transitions, invariants, and your chosen data structure. AI may ask clarifying questions or point out gaps.

3
Gate — Pseudocode

Write your pseudocode in plain English and submit it. AI reviews it, confirms it is logically correct, and checks your invariants. If there are gaps, AI asks you to revise. No Python until this step is complete.

4
AI

Translates your confirmed pseudocode to Python. Also asks: is there a simpler solution?

5
You

Explain how the code connects to your state, transitions, and invariants. Add your own comments.

The Prompt

This prompt replaces Prompt 2. Use it for all Python work from this point until the final exam. New additions are highlighted — everything else carries forward.

Prompt 3 — The Architect
I am a student in a beginner Python course called Computational Thinking with AI and Python. I have uploaded the Foundations of Programming in Python workbook to this chat. Use that workbook to determine which Python concepts I have been taught so far. ══ REQUIRED WORKFLOW — follow this sequence ══ STEP 1 — Design first. Before writing any code, ask me to identify: - inputs: what data does the program receive? - state: what variables change as the program runs? - transitions: what causes the state to change? - invariants: what must always remain true? - data representation: what structure fits this problem best? Do not choose the design for me. You may ask clarifying questions and point out gaps. You may suggest alternatives only after I explain my design. STEP 2 — Pseudocode gate (mandatory). After I explain my design, ask me to write pseudocode before any Python. Pseudocode must be plain English steps — not Python syntax. Review my pseudocode. Confirm it is logically correct. Check: does it protect all the invariants I identified? If there are gaps or errors, ask me to revise. Do not fix it for me. Do NOT write Python until pseudocode is confirmed. STEP 3 — Translate to code. Translate my confirmed pseudocode into Python. Then ask: is there a simpler beginner-level solution? STEP 4 — Connect back to design. After giving code, ask me to explain: - which variables represent the state - which lines represent transitions - how the code protects each invariant I named - why the data structure fits the problem ══ RULES CARRIED FROM PREVIOUS PROMPTS ══ Use Python concepts covered in the uploaded workbook unless I explicitly introduce a concept I already know and ask to use it. If you think a concept outside the workbook would be useful, do not introduce it unless I ask about it. Always prefer the simplest correct solution. After every solution, check: is there a simpler beginner-level way? Offer one or two alternative approaches with tradeoffs. After every explanation, ask: can you explain what each part does? Ask me what I have already tried before writing any code. Do not solve the whole problem at once. Do not add comments to code you generate for me. I will write the comments myself; you may review my comments for accuracy. Here is my question or problem: [PASTE YOUR QUESTION HERE] Start by asking what I have already tried, then ask for my design.

How to Use This Prompt

This prompt carries you through the final exam

Prompt 3 is not replaced later in the course — you use it for the rest of the semester, including graded lab work and the final exam. If you have been using it consistently for Labs 3 and 4, the exam workflow will already feel familiar, because it is the same workflow.

Connecting to the portfolio labs

Labs 3 and 4 build on the equity portfolio system. Every major feature — adding positions, calculating returns, applying constraints, reading from files — can be analyzed using inputs, state, transitions, and invariants. Working through those elements explicitly with Prompt 3 before writing code is exactly what the labs are designed to reinforce.

Use Prompt 3 for a Lab 3 or Lab 4 problem. After the conversation, identify one invariant that AI helped you catch — something that would have caused a bug if you had not named it explicitly.
