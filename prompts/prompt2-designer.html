The Designer

You know the basics. Now you learn to choose the right structure for the problem — and explain why.

Introduced: Classes 13–16 — with the Patterns & Data Structures Workbook

Building on The Explorer

Everything in Prompt 1 still applies. The four habits — ask why, demand simplicity, request alternatives, stay in scope — carry forward unchanged. Prompt 2 adds one new dimension: data representation.

Now that you have worked with lists, dictionaries, tuples, and other structures, you have the vocabulary to think about which structure fits a problem. That is a design decision, and AI should not be making it for you.

New in Prompt 2
  • Choose your data structure before AI writes any code
  • Explain why that structure fits the problem
  • Ask AI to challenge your choice — is there a better fit?
  • Ask what would break if you used a different structure
Carried forward from Prompt 1
  • Ask why after every answer
  • Demand the simplest beginner solution
  • Request at least one alternative approach
  • AI introduces only workbook concepts unless you explicitly bring in something you already know
  • AI asks what you have tried before writing code

Why Data Representation Matters

The data structure you choose shapes every line of code that follows. A poor choice makes the solution harder to write, harder to read, and more likely to break. A good choice makes the solution almost write itself.

This is a design skill — and it is one that AI will get wrong if you let it choose for you. AI will pick whatever structure makes the code easiest to generate, which is not always the structure that best fits the problem.

StructureBest whenAsk yourself
listOrder matters; items are the same type; you need to iterateDo I care about position? Will I loop through everything?
dictYou need to look things up by name or key; pairs of related valuesWill I search for items by label? Do I have key-value pairs?
tupleA fixed group of related values that should not changeIs this a record that should stay together and stay fixed?
list of dictsA collection of records, each with the same set of fieldsDo I have multiple items, each with named properties?
dict of listsGroups of items organized by category or keyDo I have categories, each containing multiple values?
The key question

Before writing a single line of code, ask: what is the natural shape of this data? A portfolio is not a list of numbers — it is a collection of positions, each with a ticker, a quantity, and a price. That description points directly to a list of dictionaries. Getting the structure right first makes everything else easier.

The Data Representation Conversation

With Prompt 2 active, your AI conversation about any non-trivial problem should include a data representation discussion before any code appears. Here is what that looks like.

What to tell AI before it writes code
  • What data structure I plan to use and why
  • What the structure looks like with a concrete example
  • Ask AI: does this structure fit the problem, or is there a better one?
  • Ask AI: what would break or become harder if I used a different structure?

Think about the equity portfolio system you will build in Lab 2. Before looking at any code, describe the data structure you would use to represent a portfolio of stocks. Include a concrete example showing what the data looks like.

The Prompt

This prompt replaces Prompt 1. Use it for all Python work from this point forward. New additions are the data representation rules — everything else carries forward from Prompt 1.

Prompt 2 — The Designer
I am a student in a beginner Python course called Computational Thinking with AI and Python. I have uploaded the Foundations of Programming in Python workbook to this chat. Use that workbook to determine which Python concepts I have been taught so far. Rules for this conversation: 1. Use Python concepts covered in the uploaded workbook unless I explicitly introduce a concept I already know and ask to use it. If a simpler solution exists using concepts I have learned, always prefer it. If you think a concept outside the workbook would be useful, do not introduce it unless I ask about it. 2. Do not just give me the answer. After every piece of code or explanation, ask me: - Do you understand why this works? - Can you explain what each part does? If I cannot explain it, help me understand before moving on. 3. Always check for simplicity. After giving any solution, ask: - Is there a simpler beginner-level way to solve this? - Does this use more code or structure than necessary? If yes, show me the simpler version. 4. Always offer alternatives. After giving a solution, describe one or two other approaches and the tradeoffs. 5. Data representation first — new rule. Before writing any code for a non-trivial problem, ask me: - What data structure do you plan to use? - Why does that structure fit this problem? - Can you show me a concrete example of what your data looks like? Do not choose the data structure for me. After I explain my choice: - Tell me whether you agree and why. - Challenge my choice: ask if a different structure would work better, and why or why not. - Ask: what would become harder or break if a different structure was used. 6. Keep me in charge. Do not solve the whole problem for me at once. Ask me what I have tried first. Ask me what part I am stuck on before writing any code. 7. Do not add comments to code you generate for me. I will write the comments myself to demonstrate that I understand the code. If I show you my own comments, you may review them and tell me whether they accurately explain the code. Here is my question or problem: [PASTE YOUR QUESTION HERE] Start by asking me what I have already tried, then ask about my data representation.

How to Use This Prompt

The new conversation pattern

With Prompt 2, every non-trivial problem should now follow this sequence: tell AI what you have tried → describe your data structure choice with a concrete example → AI challenges or confirms your choice → then code. If you skip the data representation step, AI will choose a structure for you — and you will not know if it was the right choice.

Connecting to the labs

The equity portfolio system you will build across Labs 2, 3, and 4 is a perfect test of data representation thinking. A portfolio has positions, prices, quantities, and history. Each of those has a natural structure. Working through those choices explicitly — before any code — is exactly what this prompt is designed to make you do.
