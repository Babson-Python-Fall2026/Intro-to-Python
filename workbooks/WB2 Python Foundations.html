2. Computers Store Data and Change Data

Nearly every program can be understood by asking just two questions:

  • What information is stored?
  • What operations change that information?

A spreadsheet stores numbers and updates them when formulas run. A game stores positions and scores and updates them when the player acts. A bank stores balances and changes them when transactions occur. A portfolio program stores cash and positions and changes them when a trade is recorded.

balance = 100
print(balance)
balance = balance + 25
print(balance)

Predict the output before running. Then run it. Then change the starting value and rerun.

Questions worth asking about any program

  • What value is stored before the update?
  • What value is stored after the update?
  • Which line changes the stored value?
  • What value is produced by balance + 25?
  • Would the same pattern hold if we updated the value twice?

These questions will reappear throughout the workbook in increasingly precise forms. By the end of the course they become the framework called State, Transitions, and Invariants — but the seed is here.

Two investigation tools: type() and id()

Python gives you two simple built-in functions for looking at any object. You will use them constantly during this course to investigate behavior that surprises you.

  • type(x) — tells you what kind of object x currently refers to.
  • id(x) — tells you which object x currently refers to. If id(a) == id(b), then a and b are literally the same object, not just equal objects.
x = 7
y = 3.14
name = "Alice"
items = [1, 2, 3]

print(type(x))         # <class 'int'>
print(type(name))      # <class 'str'>
print(type(items))     # <class 'list'>

print(id(x))           # a big number — the object's identity
print(id(items))       # a different big number

The exact numbers from id() don't matter. What matters is whether two ids are equal — that tells you whether two variables refer to the same object. This becomes crucial in Sections 10 and 11.

⚡ Key Idea — Number vs Numeral

7 is a number. "7" is text that happens to look like a number. Python treats them completely differently:

7 + 7        # 14   — arithmetic
"7" + "7"    # "77" — string concatenation
"7" + 7      # TypeError — Python will not guess what you meant

Most beginner bugs in this course will trace back to a value being a string when you thought it was an integer, or vice versa. type() is your first debugging tool when something doesn't behave the way you expect.

5. Working with Strings

A string is a sequence of characters. Strings appear everywhere — names, menu choices, file paths, stock tickers, dates, and reports.

text = "Babson College"

len() — the length of any sequence

len() returns the number of items in any sequence: strings, lists, tuples, dictionaries, and sets. It is one of the most frequently used built-in functions.

print(len("Babson"))            # 6   — characters in a string
print(len([10, 20, 30]))        # 3   — items in a list
print(len((1, 2)))              # 2   — items in a tuple
print(len({"AAPL": 10, "MSFT": 5}))  # 2   — keys in a dictionary

Indexing

Indexing retrieves a single item by its position. Python counts positions starting at 0, not 1. The first item is always at index 0, the second at index 1. Negative indices count from the end: -1 is the last item, -2 is second-to-last.

text = "Babson"
print(text[0])    # 'B'  — first character
print(text[1])    # 'a'  — second character
print(text[-1])   # 'n'  — last character
print(text[-2])   # 'o'  — second-to-last
text = "Babson" index: 0 1 2 3 4 5 char : B a b s o n neg idx: -6 -5 -4 -3 -2 -1

Slicing

Slicing retrieves a range of items, producing a new sequence. The general pattern is:

text[start:stop:step]

start is the index where the slice begins (included). stop is where it ends (excluded — the item at stop is not included). step is how many positions to advance each time. All three parts are optional.

text = "Babson College"

print(text[2:8])    # "bson C"   — from index 2 up to but not including 8
print(text[2:])     # "bson College"  — from index 2 to the end
print(text[:5])     # "Babso"    — from the beginning up to but not including 5
print(text[::2])    # "Bbo olg"  — every second character
print(text[-3:])    # "ege"      — last 3 characters
print(text[::-1])   # "egelloC nosbaB"  — reversed!
⚡ Key Idea — The Reverse-Slicing Surprise

If text[::-1] reverses the string, you might expect text[len(text)-1 : -1 : -1] to also reverse it. Predict the output before reading on:

text = "Babson"
print(text[::-1])                  # ?
print(text[len(text)-1 : -1 : -1]) # ?

The first reverses the string. The second produces an empty string "". Why?

When Python sees a negative index, it converts it to the equivalent positive index before computing the slice. For a 6-character string, -1 becomes 5. So text[5 : -1 : -1] is computed as text[5 : 5 : -1] — start at 5, stop at 5, going backward. That asks for nothing, so you get nothing.

The fix: when stepping backward to the start of a sequence, omit stop entirely. text[5::-1] works because no stop means "go all the way."

6. Working with Lists

A list is an ordered sequence of objects. Each item occupies a numbered position called an index, starting at 0 — exactly as with strings. Lists are mutable, which we'll explore properly in Section 11.

numbers = [3, 7, 2]
mixed   = [10, "AAPL", True]
nested  = [[1, 2], [3, 4]]
records = [{"ticker": "AAPL", "shares": 10}, {"ticker": "MSFT", "shares": 5}]

Indexing and slicing

Lists use the same indexing and slicing rules as strings.

items = [10, 20, 30, 40, 50]

print(items[0])     # 10  — first item
print(items[-1])    # 50  — last item
print(items[1:3])   # [20, 30]  — index 1 included, index 3 excluded
print(items[:2])    # [10, 20]
print(items[2:])    # [30, 40, 50]

Indexing into nested lists

When a list contains other lists, you index step by step — each [ ] reaches one level deeper.

grid = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]

print(grid[0])        # [1, 2, 3]   — the first inner list
print(grid[0][1])     # 2           — second item of the first inner list
print(grid[2][2])     # 9           — last item of the last inner list
grid[0][1] ↑ ↑ | └── second item of that inner list └──── first inner list

You'll see this pattern again in Section 14 with full multi-dimensional structures, and in Section 8 with nested dictionaries.

.sort() vs sorted()

There are two ways to sort, and they behave very differently:

numbers = [3, 1, 4, 1, 5]

numbers.sort()             # mutates in place; returns None
print(numbers)             # [1, 1, 3, 4, 5]

numbers = [3, 1, 4, 1, 5]
ordered = sorted(numbers)  # creates a new sorted list; original unchanged
print(numbers)             # [3, 1, 4, 1, 5]
print(ordered)             # [1, 1, 3, 4, 5]

Use .sort() when you don't need the original order. Use sorted() when you do.

enumerate and zip — iterating with extras

These two built-in functions are most often used with lists. enumerate gives you the index along with each item. zip pairs items from two or more sequences.

names = ["Alice", "Bob", "Cara"]
scores = [88, 91, 79]

for i, name in enumerate(names):
    print(i, name)             # 0 Alice, 1 Bob, 2 Cara

for name, score in zip(names, scores):
    print(name, score)         # Alice 88, Bob 91, Cara 79

7. Working with Tuples

A tuple is an ordered grouping that is immutable — it cannot be changed after creation. You cannot append to it, remove from it, or modify any of its items. Attempting to do so raises a TypeError.

point    = (3, 5)
date     = (2026, 1, 20)
location = (42.3, -71.2)

Tuples support indexing and iteration like lists, but they have no mutation methods.

point = (3, 5)
print(point[0])    # 3
print(point[1])    # 5

point[0] = 99      # TypeError: 'tuple' object does not support item assignment

Tuples are useful for communication and defensive programming — they signal to the reader that these values belong together as one fixed concept and should not be modified. A geographic coordinate, a date, or an RGB color value are natural tuples.

Immutability means the tuple object cannot be changed. It does not mean the variable name is permanent — you can always rebind the variable to a new tuple:

point = (3, 5)
point = (10, 20)   # rebinding — a new tuple is created, the old one is discarded

This distinction between mutating an object and rebinding a variable is the most important idea in Sections 10 and 11. Tuples are a good early example because they leave you only one option: rebind.

⚡ Key Idea — Why Tuples Can Be Dictionary Keys but Lists Cannot

Dictionary keys must be immutable. A tuple can be a key. A list cannot.

scores = {("Alice", 2026): 88, ("Bob", 2026): 91}   # works
scores = {["Alice", 2026]: 88}                       # TypeError

Why? A dictionary uses a key's value to decide where to store its entry. If the key could change after being stored, the dictionary couldn't find it again. Immutability protects that promise. You will encounter this same logic again — it's the deeper reason mutability matters at all.

8. Working with Dictionaries

A dictionary maps keys to values. A key is a label used to look up the corresponding value.

prices = {"AAPL": 205, "MSFT": 417}

Keys are like indices — but named

A list index is an integer that identifies a position: items[0] uses the number 0 to look up the first item. A dictionary generalizes this idea — instead of integers, you can use any meaningful immutable label as the key.

List: items[0] → integer index Dictionary: prices["AAPL"] → string key

Both give you fast lookup. The difference is that dictionary keys are meaningful names you choose, not positions assigned by order.

What can be a key?

Any immutable object can be a dictionary key — strings, integers, floats, booleans, and tuples (provided the tuple contains only immutable items). Lists and dictionaries cannot be keys because they are mutable.

by_name   = {"Alice": 88}            # string keys — common
by_id     = {1001: "Alice"}          # integer keys
by_coord  = {(0, 0): "origin"}       # tuple keys — useful for grids
by_list   = {[1, 2]: "nope"}         # TypeError — lists are mutable

Access and update

prices = {"AAPL": 205, "MSFT": 417}

print(prices["AAPL"])      # 205  — look up by key
prices["GOOG"] = 180       # add a new key/value pair
prices["AAPL"] = 210       # update an existing value

.get() — safer lookup

d["missing"] raises a KeyError and crashes. d.get("missing") returns None. d.get("missing", 0) returns 0 — the default you supplied. This is one of the most useful patterns in beginner Python:

counts = {"AAPL": 3, "MSFT": 2}

# Count safely, treating missing tickers as 0
current = counts.get("GOOG", 0)
counts["GOOG"] = current + 1

Indexing into nested dictionaries

Just as with lists, you step into nested dictionaries one level at a time.

portfolio = {
    "client": "Alice",
    "cash": 12000,
    "positions": [
        {"ticker": "AAPL", "shares": 10},
        {"ticker": "MSFT", "shares": 5}

9. Three Ways to Talk to an Object ⚡ KEY IDEA

Stop and look at the code you've been writing. You've been asking objects to do things in three completely different ways, and Python uses different syntax for each. Once you see the pattern, a lot of Python's apparent inconsistency becomes one elegant idea.

⚡ The Pattern 
portfolio["AAPL"]    # square brackets — key or index lookup
numbers.append(4)    # dot notation    — method call (object does something to itself)
len(numbers)         # parentheses     — function call (something done to the object)

Three syntaxes. Three different relationships to the object.

1. Brackets — lookup by key or index

Brackets ask: "give me the item stored at this position or under this name." The object is being indexed into.

text[0]             # first character of a string
items[3]            # fourth item of a list
prices["AAPL"]      # value stored under key "AAPL"
grid[1][2]          # nested — second row, third column

2. Dot notation — methods the object knows about

Dot notation says: "object, do this thing you know how to do." Methods are functions attached to a specific type. append exists on lists, not on strings. upper exists on strings, not on lists.

numbers.append(4)   # lists know how to append
text.upper()        # strings know how to uppercase
prices.get("X", 0)  # dictionaries know how to do safe lookup

3. Functions — something done to the object from outside

A function takes the object as an argument and does something with it. Functions work on many types — len works on strings, lists, tuples, dictionaries, and sets, because all of them know how to report their length.

len(text)           # works on strings, lists, tuples, dicts, sets
type(items)         # works on any object
sorted(numbers)     # works on any sequence
id(portfolio)       # works on any object

Why this matters

When you're stuck, ask: which of the three should I be using? Some things you reach for naturally with brackets — looking up an item. Some you reach for with a method — telling the object to change itself. Some you reach for with a function — asking something general about the object.

The same object often supports all three. A list can be indexed (items[0]), can have methods called on it (items.append(5)), and can be passed to functions (len(items)). They are not competing — they are three different relationships.

10. Variables, References, and Aliasing

A variable is not an object. A variable is a label that refers to an object. It is more accurate to think of a variable as a sticky note than as a box that holds a value.

variable name → reference → object
a = [1, 2]
b = a

print(id(a))
print(id(b))     # same number — same object
a ─┐ ├──► [1, 2] b ─┘

This is called aliasing. Two variables are different labels for the same object. If you change the object through a, the change is visible through b — because they refer to the same thing.

Aliasing with a mutable object

a = [1, 2]
b = a
a.append(3)
print(b)    # [1, 2, 3] — b sees the change

This is exactly the phenomenon you saw in Section 1. There is only one list. a and b are two labels for it.

Aliasing with an immutable object

x = 10
y = x
x = 20         # rebinding — x now refers to a different object
print(y)       # 10 — y still refers to the original
Before rebinding: After x = 20: x ─┐ x ──► 20 ├──► 10 y ──► 10 y ─┘

Integers cannot be mutated — you cannot reach into an integer and change its value. So aliasing them is always safe. The risk from aliasing comes only from mutable objects like lists and dictionaries.

⚡ Key Idea — This Explains Functions, Too

When you pass a variable to a function, Python passes the reference, not a copy of the object. Inside the function, the parameter is just another alias for the same object. Predict what happens:

    items.append(1)

print(my_list)        # ?

Output: [10, 20, 1]. The function mutated the original list because it had a reference to the same object. This surprises beginners constantly — they assume functions get a private copy. They don't. Aliasing explains why.

11. Mutability, Rebinding, and Copying ⚡ KEY IDEA

This is the most important conceptual section in the workbook. Understanding it will prevent an entire class of confusing bugs and will give you the leverage you need to direct AI confidently.

The core distinction: mutating vs rebinding

There are two completely different things that can happen when you "change" something in Python. You must be able to tell them apart:

  • Mutating an object — the object itself changes. Its contents are modified in place. Every variable that refers to that object sees the new contents.
  • Rebinding a variable — the variable is made to point to a different object. The original object is untouched. Other variables that still refer to the original object are unaffected.

Mutation changes what is inside the box. Rebinding moves the label to a different box.

Mutation: visible through all aliases

a = [1, 2]
b = a              # b is an alias — same object

b.append(3)        # mutation — the object itself changes
print(a)           # [1, 2, 3] — a sees the change too
print(b)           # [1, 2, 3]
print(id(a) == id(b))   # True — still the same object
a ─┐ ├──► [1, 2, 3] ← the one object was mutated b ─┘

Rebinding: only one variable changes

a = [1, 2]
b = a              # b is an alias

b = b + [3]        # rebinding — b now points to a new list
print(a)           # [1, 2]       — original unchanged
print(b)           # [1, 2, 3]    — new object
print(id(a) == id(b))   # False — different objects now
a ──► [1, 2] ← original, unchanged b ──► [1, 2, 3] ← brand new object

Immutable objects: only rebinding is possible

Integers, floats, strings, and tuples are immutable — they have no methods that change them in place. When their value appears to change, Python is always creating a new object and rebinding the variable:

x = 10
y = x
x = 20         # rebinding — x points to a new integer object
print(x)       # 20
print(y)       # 10 — y still refers to the original

This is why aliasing integers and strings is always safe — you cannot mutate them at all.

Copying fixes the aliasing problem for mutable objects

a = [1, 2, 3]
b = a.copy()       # b is a new, independent list
b.append(4)
print(a)           # [1, 2, 3]    — unaffected
print(b)           # [1, 2, 3, 4]

Shallow vs deep copy

a.copy() makes a shallow copy — a new outer list, but the inner objects are still shared. For a flat list of numbers or strings that's fine, because those items are immutable. But for a list of lists, shallow copying leaves you with a new outer list whose inner lists are still aliased:

import copy

a = [[1, 2], [3, 4]]
b = a.copy()          # shallow copy
b[0].append(99)
print(a)              # [[1, 2, 99], [3, 4]]  — inner list was shared!

a = [[1, 2], [3, 4]]
c = copy.deepcopy(a)  # deep copy — all inner objects also copied
c[0].append(99)
print(a)              # [[1, 2], [3, 4]]  — unaffected

Common tracing mistakes

Three mistakes show up reliably. Recognizing them is half the battle.

  • Mistake 1: Updating a variable before recording its previous value. If a row says "after update," you have to actually wait until after the update to fill it in. Skipping ahead loses the step-by-step record that makes tracing useful.

In a while loop, you must update the variable explicitly inside the body — or the loop runs forever. Trace tables surface infinite loops immediately because the condition column never changes.
  • Mistake 3: Tracing in your head instead of on paper. Once a problem has more than two variables and more than three iterations, head-tracing breaks down. Write it out. There is no shame in this — professionals do it constantly when reasoning about tricky code.

Function anatomy

def add(a, b):
    return a + b

print(add(3, 4))    # 7
  • Function signature: add(a, b)
  • Parameters: names in the definition (a, b)
  • Arguments: values passed in the call (3, 4)
  • Return value: the value sent back to the caller

Default arguments

You can give a parameter a default value. If the caller omits that argument, the default is used.

def greet(name, greeting="Hello"):
    print(f"{greeting}, {name}!")

greet("Alice")                # Hello, Alice!
greet("Bob", "Hi")            # Hi, Bob!
greet("Carol", greeting="Hey")  # Hey, Carol!

return vs print

def square(x):
    return x * x      # sends the value back

def show_square(x):
    print(x * x)      # displays it; returns nothing

return hands a value back to the caller, who can use it. print just displays the value. They are completely different — and confusing them is a common bug.

Remember from Section 10: when you pass a list or dictionary to a function, the function receives a reference to the same object, not a copy. Mutations inside the function affect the original.

18. Files and JSON

Programs often need to save data between runs. Files let information persist after the program stops.

Four ways to read a text file

with open("data.txt", "r") as f:
    content = f.read()       # reads the entire file as one string

with open("data.txt", "r") as f:
    line = f.readline()      # reads one line; returns "" when no more

with open("data.txt", "r") as f:
    lines = f.readlines()    # creates a list of lines

with open("data.txt", "r") as f:
    for line in f:           # iterate one line at a time — most common
        print(line)

The for line in f: idiom is the one you'll use most often. It reads the file lazily, one line at a time, without ever loading the whole file into memory. For very large files this matters; for small files all four approaches work.

Writing and appending

with open("notes.txt", "w") as f:    # "w" = write (overwrites existing file)
    f.write("Hello\n")
    f.write("World\n")

with open("notes.txt", "a") as f:    # "a" = append (adds to existing file)
    f.write("Another line\n")

Mode "w" overwrites any existing file. Mode "a" adds to the end. Choose carefully — "w" on a file with existing content destroys that content.

First pattern: CSV

a) Create the object in Python

positions = [("AAPL", 10), ("MSFT", 5)]

b) Write to CSV

with open("positions.csv", "w") as f:
    f.write("ticker,shares\n")
    for ticker, shares in positions:
        f.write(f"{ticker},{shares}\n")

c) Read and recreate the object

positions = []
with open("positions.csv", "r") as f:
    next(f)   # skip the header line
    for line in f:
        ticker, shares = line.strip().split(",")
        positions.append((ticker, int(shares)))

Second pattern: JSON

a) Create the object

positions = [
    {"ticker": "AAPL", "shares": 10},
    {"ticker": "MSFT", "shares": 5}
]

b) Write to JSON

import json
with open("positions.json", "w") as f:
    json.dump(positions, f, indent=2)

c) Read and recreate the object

import json
with open("positions.json", "r") as f:
    positions = json.load(f)

With CSV, you manually split strings, convert types, and rebuild the object. With JSON, the structure is already represented — what you wrote is what you get back. That is why JSON is simpler for structured data.

19. Handling Errors with try / except

Errors in Python raise exceptions. If an exception is not handled, the program crashes. The try / except block lets you catch errors and respond gracefully instead of stopping.

Basic pattern

try:
    result = int(input("Enter a number: "))
    print("You entered:", result)
except ValueError:
    print("That was not a valid number.")

Python runs the code in the try block. If a ValueError is raised, execution jumps to the except block. If no error occurs, the except block is skipped entirely.

Handling file errors

import json

try:
    with open("prices.json", "r") as f:
        data = json.load(f)
except FileNotFoundError:
    print("File not found. Starting with empty data.")
    data = []

Handling multiple exception types

try:
    value = int(input("Enter shares: "))
    price = float(input("Enter price: "))
    total = value * price
    print(f"Total value: {total:.2f}")
except ValueError:
    print("Please enter a valid number.")
except ZeroDivisionError:
    print("Cannot divide by zero.")

else and finally

try:
    result = int(input("Enter a number: "))
except ValueError:
    print("Invalid input.")
else:
    print("Success:", result)    # runs only if no exception
finally:
    print("Done.")               # always runs

20. Debugging — A Practical Walkthrough ⚡ KEY IDEA

Every section of this workbook prepared you for this one. Debugging is the skill that makes everything else useful — because everyone writes code that doesn't work the first time, and the difference between a programmer who gets stuck and one who doesn't is the discipline of investigation, not raw talent.

You already have the investigation tools — type(), id(), print(), the trace table, and scratch.py. This section shows them in action on three real bugs.

The general strategy

When something doesn't work, do not stare at the code. Investigate.

  1. Simplify. Strip the program down to the smallest version that still shows the problem. Most bugs disappear or become obvious in the smaller version.
  2. Make the invisible visible. Add print() statements that show variable values at each step. Use type() if you suspect a value is the wrong kind of object. Use id() if you suspect aliasing.
  3. Trace it. If the bug is in a loop, fill in a trace table by hand. If it's in a function, write down what each argument binds to.
  4. Verify your assumptions. Almost every bug comes from an assumption that turned out to be false. Test the assumption explicitly before moving on.
  5. Reproduce in scratch.py. Once you suspect a specific cause, build a 3-line example that isolates it. If the example reproduces the bug, you've found it. If it doesn't, your suspicion was wrong — try the next one.

Bug 1 — Type confusion

A student writes a program to compute total revenue from a list of prices, but it crashes with an error.

prices = ["10", "20", "30"]
total = 0
for p in prices:
    total = total + p
print(total)

Running this raises TypeError: unsupported operand type(s) for +: 'int' and 'str'.

Step 1 — make the invisible visible. The error mentions int and str. Which is which?

print(type(total))    # <class 'int'>
print(type(p))        # <class 'str'>

Step 2 — verify the assumption. The student assumed the prices were numbers. They are not — they are strings that look like numbers. This is the "number vs numeral" idea from Section 3 showing up as a real bug.

Step 3 — fix.

prices = ["10", "20", "30"]
total = 0
for p in prices:
    total = total + int(p)     # convert each string to an integer
print(total)                   # 60

The lesson: when the error mentions a type, the first move is to check the types. type() answers the question instantly.

Bug 2 — Aliasing

A student writes a function that should give every player a fresh inventory, but something strange happens.

def make_player(name, starting_items):
    return {"name": name, "items": starting_items}

starter = []
alice = make_player("Alice", starter)
bob   = make_player("Bob", starter)

alice["items"].append("sword")
print(alice["items"])   # ['sword']
print(bob["items"])     # ['sword']   — Bob has Alice's sword!

Step 1 — make the invisible visible. The student assumed Alice and Bob have separate inventories. Are they actually separate?

print(id(alice["items"]))    # 140234...
print(id(bob["items"]))      # 140234...   — same number!

Step 2 — diagnose. Same id means same object. Alice's items list and Bob's items list are aliases for the original starter list. Mutating one mutates the other. This is Section 10 made painful.

Step 3 — fix.

def make_player(name, starting_items):
    return {"name": name, "items": starting_items.copy()}

Now each player gets a fresh copy of the starting items.

The lesson: when you write "two variables should be independent" and they aren't, id() tells you whether they share an object. The fix is almost always to .copy() the mutable input.

Bug 3 — Off-by-one in a loop

A student writes a loop that should print the first five even numbers but prints six numbers instead.

n = 0
count = 0
while count <= 5:
    if n % 2 == 0:
        print(n)
        count = count + 1
    n = n + 1

Step 1 — trace it. Fill in a trace table for the first several iterations.

Step 2 — diagnose. The loop condition is count <= 5. The student wanted "stop after five." But <= 5 includes 5, so the loop runs while count is 0, 1, 2, 3, 4, AND 5 — six iterations, not five. This is a classic off-by-one error.

Step 3 — fix.

The lesson: when a loop runs one too many or one too few times, trace the boundary explicitly. The error is almost always at the first or last iteration — the trace table makes that boundary visible.

⚡ Key Idea — Debugging Is The Job

Professional programmers spend more time debugging than writing new code. The investigation skills in this section — checking types, checking identity, tracing loops, simplifying to the smallest reproducer — are not training wheels. They are the actual core of the work. Get good at them and you will be able to fix code you didn't write, including code AI wrote.

22. Glossary

A reference for the vocabulary used in this workbook. Useful during the midterm when a term feels half-remembered. Italicized terms refer to other glossary entries.

ABCDEFIKLMOPRSTV

A

accumulator
A variable that builds up a result across the iterations of a loop. The accumulator pattern is initialize, loop, update. Examples: a running total, a count, a list under construction, a running best.
alias
Two variables that refer to the same object. Created by an assignment like b = a when a refers to a mutable object. Mutating through one alias is visible through the other.
argument
The value you pass to a function when you call it. add(3, 4) has arguments 3 and 4. Distinct from parameter.

B

bool
A type with exactly two values: True and False. Booleans are the result of comparisons and the basis of every conditional in a program.
break
A statement that exits the nearest enclosing loop immediately. Distinct from continue, which skips to the next iteration.

C

continue
A statement that skips the rest of the current iteration and proceeds to the next one. The loop itself does not exit.
copy (shallow)
A new outer object containing references to the same inner objects as the original. For a flat list of numbers or strings this gives you full independence; for a list of lists, the inner lists are still shared.
copy (deep)
A fully independent copy in which every nested object is also copied. Required when nested mutable structures need to be independent. Available as copy.deepcopy(x).

D

default argument
A value given to a parameter that is used if the caller omits the corresponding argument. Defined in the function signature: def greet(name, greeting="Hello"):.
dictionary (dict)
A built-in mutable type that maps keys to values. Keys must be immutable. Useful when you need fast lookup by a meaningful name.

E

enumerate
A built-in function that pairs each item of an iterable with its index. Use it when you want both during iteration: for i, x in enumerate(items):.
exception
A signal raised when something goes wrong during execution. Common types include ValueError, TypeError, KeyError, IndexError, FileNotFoundError. Handled with try / except.
expression
Code that produces a value. 3 + 5, len(items), and x > 0 are all expressions. Distinct from a statement, which performs an action.

F

f-string
A string literal prefixed with f that lets you embed Python expressions and formatting directives inside curly braces. f"{price:>10.2f}" right-aligns price in a width-10 field with 2 decimals.
function
A named, reusable piece of code that takes arguments, executes a body, and optionally returns a value. The basic unit of decomposition.

I

id()
A built-in function that returns a number uniquely identifying an object. If id(a) == id(b), a and b are literally the same object — they are aliases. Investigation tool number one for aliasing bugs.
immutable
An object whose value cannot be changed after creation. Integers, floats, strings, tuples, and frozensets are immutable in Python. Immutable objects can be safely used as dictionary keys.
index
An integer that identifies a position in a sequence. Python uses zero-based indexing — the first item is at index 0. Negative indices count from the end (-1 is the last item).
invariant
A condition that must always be true while a program is running. Example: a bank balance should never be negative. Identifying invariants is a core skill in the STI framework (Workbook 3).

K

key
The label used to look up a value in a dictionary. Keys must be immutable — strings, integers, floats, booleans, and tuples of immutable values all work; lists and dictionaries do not.

L

len()
A built-in function that returns the number of items in a sequence. Works on strings, lists, tuples, dictionaries, and sets.
list
A built-in mutable ordered sequence of items. Items are accessed by integer index. Lists support many mutation methods (append, pop, sort, etc.).

M

method
A function that belongs to an object and is called with dot notation. items.append(5) calls the append method on the list items. Different types have different methods.
module
A file containing Python code that can be imported into another file. Modules from the standard library (math, json, os, random) cover a wide range of common needs.
mutable
An object whose contents can be changed in place after creation. Lists, dictionaries, and sets are mutable. Mutating a mutable object affects every alias.
mutation
Changing the contents of an existing object in place. Distinct from rebinding, which makes a variable point to a different object. a.append(3) mutates; a = a + [3] rebinds.

O

object
Anything you can refer to with a variable in Python. Every object has a type, an identity (returned by id()), and a set of operations you can perform on it. Objects bundle data with operations.
operation
A computation that transforms data, performed inside an expression. Arithmetic (+, *), comparisons (<, ==), function calls, and method calls are all operations.

P

parameter
A name in a function definition that will receive an argument when the function is called. def add(a, b): has parameters a and b. Distinct from argument, which is the value passed in.
predict-then-run
The recommended habit in this workbook: write down what you think the code will produce before running it. The gap between prediction and actual output is the most valuable signal you have for what you don't yet understand.

R

range()
A built-in function that generates a sequence of integers. range(stop), range(start, stop), and range(start, stop, step) are the three forms. The stop value is excluded.
rebinding
Making a variable refer to a different object. x = 20 when x previously referred to 10 rebinds x. Distinct from mutation; rebinding doesn't affect other aliases.
reference
The mechanism by which a variable points to an object. A variable does not contain a value — it contains a reference to a value. Multiple variables can hold references to the same object (see alias).
return
A statement that exits a function and sends a value back to the caller. Distinct from print, which displays a value but returns nothing.

S

scratch.py
A small file used for experiments. The recommended habit when something is unclear: open scratch.py, write three to ten lines that test the smallest version of the question, predict, run, observe.
signature
The "shape" of a function: its name and its parameter list. add(a, b) is the signature of a function that takes two arguments.
slice
A subsequence extracted from a string, list, or tuple. The general form is seq[start:stop:step]. The stop index is excluded.
state
The information a program holds that changes as it runs. Identifying state is a core STI skill (Workbook 3). Trace tables are pictures of state changing over time.
statement
A line of code that performs an action — an assignment, a print, a control-flow instruction. Distinct from an expression, which produces a value.
STI
State, Transitions, Invariants — the computational thinking framework developed in Workbook 3. The bridge between Python fluency and program design.
string
A built-in immutable sequence of characters. Created with quotes: "hello" or 'hello'. Supports indexing, slicing, and many methods.

T

trace table
A grid showing how each variable changes across the iterations of a loop or the calls of a function. The primary tool for verifying behavior without running code.
transition
An operation that changes the state of a system from one valid configuration to another. In a bank account, deposit and withdraw are transitions. STI concept.
try / except
The Python mechanism for catching exceptions. Code in the try block runs normally; if an exception of the matching type is raised, the except block runs instead of crashing.
tuple
A built-in immutable ordered grouping. Useful for fixed records, coordinates, dates, and as dictionary keys. Created with parentheses: (3, 5).
type()
A built-in function that reports what kind of object a value is. The first investigation tool to reach for when an operation fails for "type" reasons.

V

variable
A name that refers to an object. Not the same as the object itself — a variable is a label, not a box. Multiple variables can refer to the same object.
