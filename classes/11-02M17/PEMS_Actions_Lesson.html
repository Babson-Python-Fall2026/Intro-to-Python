4 · The data model: what actions act on

Before writing actions, you need to know the data they change. All business data lives in pems.json. It nests four levels deep:

pems.json a dict keyed by PM initials └── "RSS" a dict with one key: "clients" └── clients a list of client dicts └── client name, email, phone, transactions └── transactions a list of transaction dicts

A client

Every client has exactly these keys:

CLIENT_KEYS = ["name", "email", "phone", "transactions"]

"transactions" is a list. A new client starts with one transaction in it: the starting cash.

A transaction

Every transaction has exactly these keys, in this order, whatever its type:

TRANSACTION_KEYS = ["trans_id", "trd_day", "trans_type", "ticker", "shares",
                    "cost_per_share", "total", "div_amnt",
                    "shares_before", "shares_after"]

A key that doesn't apply to a transaction is set to None. That way, any code can read any key of any transaction without a KeyError.

Example: one client after Create Client

{
  "RSS": {
    "clients": [
      {
        "name": "Ada Lovelace",
        "email": "ada@example.com",
        "phone": "555-0101",
        "transactions": [
          {
            "trans_id": 1,
            "trd_day": 1,
            "trans_type": "CONTRIBUTION",
            "ticker": "$$$$",
            "shares": 1000.0,
            "cost_per_share": 1.0,
            "total": 1000.0,
            "div_amnt": null,
            "shares_before": null,
            "shares_after": null
          }
        ]
      }
    ]
  }
}

Conventions

  • Keys are lowercase; values are uppercase: "trans_type": "CONTRIBUTION".
  • Cash is treated like a security. Its ticker is "$$$$" and it is priced at 1.0, so 1,000 dollars is 1,000 "shares" of cash.
  • All amounts are positive. Direction comes from trans_type: a withdrawal is a positive total with trans_type "WITHDRAWAL".
  • div_amnt, shares_before, and shares_after are for dividends and splits, which PEMS handles later. For anything you enter, they are None.

5 · What an action is

An action is a function that runs when the user chooses a menu option. Every action follows the same contract:

  • It takes one parameter, state: a dictionary holding everything an action might need, such as the PM, their clients, the selected client, and the trade day.
  • It does its work by changing state. For example, Select Client records the chosen client in state['client_idx'].
  • It returns False when the user should stay on the current menu (nothing was done, or the user cancelled). Any other return value lets navigation continue.

The actions live in actions.py, along with an actions dictionary that maps each action's name to its function. Part 2 shows how a name in menus.json becomes a function call.
