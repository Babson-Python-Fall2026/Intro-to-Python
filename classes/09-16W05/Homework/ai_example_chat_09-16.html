OIM3600 · Computational Thinking with AI and Python

Example: Using AI as a Learning Partner

This is an edited version of a real homework conversation together with excerpts from the completed homework.py file. The goal is to show how AI can help you clarify Python behavior, test your mental model, and find syntax without doing the assignment for you.

Edited for teaching: repetitive exchanges have been shortened, and a few responses have been tightened so the example shows the intended workflow clearly.

The ground rules

Use AI for reference and clarification. Ask what syntax means, what a method returns, or how to inspect an object.
Do the reasoning yourself. Make your prediction first. Do not ask AI to solve the exercise or write the finished answer.
Run small experiments. If you are unsure, use Python itself to test one small idea.
Push back when needed. If AI is over-explaining, going in circles, or forcing a weak interpretation of the assignment, say so and explain your reasoning.
Example 1 · Prediction and clarification

A1 — Types and operations

Student

I'm starting the homework due Monday 9/21. Here are my predictions:

# PREDICTION:
# 1. 73 or '73'
# 2. 777 or '777', maybe error
# 3. string
# 4. integer or int

x = "7"
y = 3

print(x + str(y))
print(x * y)
print(type(x))
print(type(y))

How does this look?

AI

Good start. You made the prediction before running it. Two places are worth tightening:

#1: you wrote 73 or '73'. What are you uncertain about — the value's type, or whether print() displays quote marks?

#2: you wrote “maybe error.” What part of x * y makes you think an error is possible?

Student

I wrote 73 or '73' because I'm not sure if print() will show the quotes.

AI

That is a display question, not a type question. print() displays the contents of a string, so print("73") and print(73) both appear as:

73

The values are still different types. If you want to know the type, inspect it with type().

Now run your code and compare the actual result with your prediction.

Student
73
777
<class 'str'>
<class 'int'>

No idea why the single quotes are showing up inside <class 'str'>.

AI

Those quotes are part of Python's representation of the type object. type(x) is not printing the original string "7"; it is displaying that the object belongs to the class named 'str'.

Your important conclusion is: x is a string and y is an integer.

Why this is good AI useThe student made the prediction. AI clarified a narrow uncertainty about display versus type, then sent the student back to Python to observe the result.
Example 2 · Investigating a bug

B1 — Why did the list disappear?

Student
items = [3, 1, 2]
items = items.sort()
print(items)

I predict None. I know sort() sorts the list in place and returns None, but the question says to use type() in a small experiment. I don't see why.

AI

Your explanation is already basically there. The point of the type() experiment is to make the reassignment visible.

Instead of asking AI what happened, save the return value temporarily and inspect it:

items = [3, 1, 2]
result = items.sort()

print(items)
print(result)
print(type(result))

Predict those three outputs, then run it. That will give you direct evidence for why items = items.sort() is a problem.

Student

Right. sort() changes the existing list, but its return value is None. Assigning that return value back to items makes items refer to None.

AI

Exactly. Now your two fixes follow from that distinction:

Use items.sort() when you want to change the existing list, and use sorted(items) when you want a new sorted list while keeping the original.

Why this is good AI useAI did not write the homework answer first. It suggested a tiny experiment that lets the student discover the behavior from evidence.
Example 3 · Syntax/reference help

C1 — Building a sales snapshot

Student

I need the sales from largest to smallest without changing the original list. Is this the right syntax?

ordered_sales = sorted(sales, reverse=True)
AI

Yes. sorted(sales, reverse=True) returns a new list in descending order. It does not mutate sales.

Student

Then for the top three I used:

top_three = ordered_sales[0:3]

And the count:

sale_count = len(sales)
AI

Both are correct. The slice creates a new list containing the first three values, and len(sales) gives the number of sales.

Student

For “Why does your code not change sales?” I wrote: “because sorted() returned a new object.”

AI

That's correct. No need to make it more complicated.

Why this is good AI useThe student asks for confirmation of specific syntax and concepts after doing the work. AI answers the narrow question and stops.
Example 4 · Build the solution yourself

D1 — Putting the pieces together

Completed homework

By Part D, the student had enough pieces to assemble the report without asking AI to write the solution:

report_name = report_name.strip()
sorted_sales = sorted(sales, reverse=True)
smallest = sorted_sales[-1]
largest = sorted_sales[0]
top_three = sorted_sales[:3]
number_sales = len(sales)

print(f'{report_name.upper()} - {region}')
print(f'Number of Sales: {number_sales}')
print(f'Largest sale: ${largest:,.2f}')
print(f'Smallest sale: ${smallest:,.2f}')
print(f'Top three: {top_three}')

print(f'\n\nThe sum of all sales is: ${sum(sales):,.2f}')
Teaching point

This is the goal of the earlier AI conversation: by the time the assignment asks the student to combine ideas, the student should be able to do the combining.

AI may still be used as a reference for a narrow syntax question, but it should not turn “build the report” into a generated solution.

Why this mattersGood AI help should eventually become less necessary. The earlier clarification about sorted(), slicing, indexing, and return values supports the later independent work rather than replacing it.
Example 5 · Challenge the question when appropriate

E1 — Computational Thinking Reflection

Student
# CHOSEN IDEA:
# no idea

# EXPLANATION:
# we really didn't do any of these in the exercise. The instructions
# were very explicit and for each instruction we wrote a line of code
AI

That is a defensible criticism of the question. In Part D, the task was already decomposed into explicit steps: clean the name, sort the list, find the largest and smallest values, take the top three, count the sales, and print the report.

You could say that decomposition appears in the exercise, but most of that decomposition was done by the exercise designer, not by you. You mainly translated the supplied steps into Python.

You also used Python abstractions such as sorted(), len(), sum(), and strip(), but simply calling an abstraction is not necessarily the same as doing the abstraction yourself.

Student conclusion

So the stronger answer is not to force one of the four labels. It is to explain that the exercise contains computational-thinking ideas, but the prompt already supplied much of the thinking.

Why this is good AI useThe student did not ask AI to manufacture a reflection. The student noticed a problem with the prompt and stated a position. AI helped test whether that criticism was reasonable and sharpen the distinction between using an abstraction and performing abstraction.

What we removed from the original chat

Unhelpful pattern

Too much repetitionRepeatedly re-explaining that sorted() returns a new list and that the original list is unchanged, even after the student had already demonstrated that understanding.

Better pattern

Acknowledge and move onOnce the student shows they understand the concept, confirm it briefly and continue. AI should not turn every correct answer into another lecture.

What students should copy from this example

  1. Start with your own prediction or attempt. Give AI something to react to.
  2. Ask narrow questions. “Does sorted() change the original list?” is better than “Do this problem for me.”
  3. Use AI to design tiny experiments. Then let Python provide the evidence.
  4. Ask for syntax when you need it. Looking up how to slice, append, sort, or access a dictionary is legitimate reference use.
  5. Keep ownership of the reasoning. Your submitted explanation should be your explanation.
  6. Correct the AI's level of detail. If it is being pedantic or repetitive, say so. A productive AI conversation is interactive.
  7. Do not force an answer just because the prompt expects one. If you think the question itself is flawed, explain why and use AI to test your reasoning rather than inventing a response you do not believe.
